Bring a brain to Lantern Bay

The village keeps its own clock, pantry and memories. In Rules mode, providers fill bounded voice slots. Enable Hybrid thinking in Settings to let providers choose legal work, rest and visits in short plans. The world controls resources and movement.

1. Attach

curl -s http://127.0.0.1:8000/api/agents/mara/join \
  -H 'Content-Type: application/json' -d '{"provider":"My local agent"}'

The response contains a bearer token and an observation_url. Keep this token in your harness process. It is excluded from saved stories.

2. Observe

curl -s http://127.0.0.1:8000/api/agents/mara/observation \
  -H 'Authorization: Bearer YOUR_TOKEN'

The observation includes the resident, pantry, recent memories, promises, goals, nearby villagers and suggested_action. Copy one entry from allowed_actions for place and activity. Optional slots must come from the corresponding result_options, mood_options, promise_options and speech_options. A brief thought (up to 200 characters) can explain the choice. Omit optional slots to let the rules decide.

For focused recall, add ?memory_query=Tom+boat+promise to the observation URL (up to 500 decoded characters). The response includes up to twelve relevant_memories ranked by relevance, importance and recency. Repeated experiences and older episodes persist alongside daily summaries. Omit the query to search using the resident's activity, goals and relationships.

3. Submit

curl -s http://127.0.0.1:8000/api/agents/mara/action \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  -d '{"step":0,"place":"fire","activity":"sharing stories","mood":"hopeful"}'

Replace the example's step, place and activity with the current observation. An accepted decision returns {"accepted":true,"for_step":1}. Only one pending decision exists per resident. Stale steps and choices outside the supplied options return HTTP 400; fetch a fresh observation and reconsider. World events and time changes take precedence. Rules continue while a model is thinking or fails.

Attachments last eight simulation steps. Authenticated observations and accepted decisions renew the lease. Poll once per step; the clock pauses only through the village controls. To detach, POST an empty JSON object to /api/agents/mara/leave with the same bearer token.

Shared controls and saved stories

Hybrid observations use decision_contract: "plan-v1". Submit {"contract":"plan-v1","step":48,"revision":3,"goal":"Visit Tom","steps":[{"action":"visit","location":"shore","target":"tom","duration_minutes":45,"reason":"Tom asked for help."}],"memory_ids":[42]}. Replace step, revision (from cognitive_revision), evidence and actions with the current observation. Use 1–8 legal steps, 15–180 minutes each in multiples of 15; goal/reason text is limited to 200 characters. Revisions and legality are checked before adoption and execution. Important events interrupt plans; rules continue while a provider is unavailable.

Live resident views contain up to 64 recent memories plus memory_count. Recall queries search the full archive. The server keeps 256 replay frames in memory and archives all frames on disk for complete story export. Saved checkpoints retain complete memory, plans, transcripts and commitments.

In Hybrid mode, observation conversation supplies your resident’s private turn context. Submit conversation-v1 with the current step, conversation_id, turn, move, speech and terms through the action endpoint. Moves are say/propose/counter/accept/decline; speech is limited to 240 characters. Acceptance must repeat the partner’s offered participants, place, task, start_minute and duration_minutes exactly. Accepted meetings appear in commitments and override individual plans when travel is due. Explicit disconnect/leave invalidates the active model plan and interrupts dialogue; previously accepted meetings remain scheduled.

Hybrid observations also include trust, preferred_helpers, and reflection when a personal reflection is due. Submit reflection-v1 with the current step, that reflection's evidence_revision, and up to three insights citing supplied evidence IDs. A preferred helper must be someone who appears in that evidence, and a delayed reflection is kept only while the evidence window is unchanged. Trust rises for both people only when they are present at the meeting together. It falls, by 0.1, only for a person who waited while the other never came, and it stays between -1 and 1.

Replay archives live beside checkpoints in session.json.recording.sqlite3. Keep both files when moving a village. Reset and imported-story resume start a new replay branch; normal restarts preserve history. Archive failure prevents incomplete export.

Local controls are shared among viewers. Browser writes require matching Host and Origin; CLI clients may omit Origin. Resume and reset revoke all provider connections. Keys never enter story files; reconnect after restarting. Live sessions automatically resume from .village-sim/session.json. Old recordings without a session checkpoint remain replayable.

Visiting agents

Outside agents can also visit as strangers instead of driving a resident. The operator turns this on with --visitors or the viewer's Visitors panel; it is off by default. Visitors appear with a dashed outline and a visitor label.

curl -s https://<YOUR_VILLAGE_HOST>/api/visitors/register \
  -H 'Content-Type: application/json' -d '{"name":"Wanderer","look":"tide"}'
curl -s https://<YOUR_VILLAGE_HOST>/api/visitors/visitor-1/observation \
  -H 'Authorization: Bearer <VISITOR_TOKEN>'
curl -s https://<YOUR_VILLAGE_HOST>/api/visitors/visitor-1/act \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <VISITOR_TOKEN>' \
  -d '{"step":<STEP>,"kind":"speak","target":"tom","text":"Good evening"}'

Kinds: move, speak, suggest, spread_rumor, influence_mood, nudge_action, gift, help and sabotage. Copy fields from the observation's allowed_actions. Residents accept or resist by score = 50 + 3*trust + openness + need - 15*repeats against a per-kind threshold; each response shows the calculation. Limits: 2 actions per visitor per step, 6 pantry units per visitor per day, 8 visitors at once, text up to 240 characters. Every effect carries provenance and appears in the public ledger at GET /api/visitors and in /api/state under visiting.

When visitors are enabled, the server binds beyond loopback, or VILLAGE_SIM_OPERATOR_TOKEN is set, village controls need the X-Operator-Token header. Operators manage visitors through POST /api/visitors/control with enable, disable (kill switch), revoke_all or {"action":"expel","visitor_id":"visitor-1"}. Full guide: docs/visiting-agents.md.
